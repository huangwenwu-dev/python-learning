## 手写 RAG(第11周) vs 用框架(第12周)

### 一、框架帮我省掉了什么

| 环节 | 第11周我自己写的 | 第12周谁替我写了 |
|---|---|---|
| 调 API | `client.chat.completions.create(...)` 一整套样板 | `agent.invoke()` 内部替我调用并解析返回 |
| 工具调用解析 | 手动 `if "get_weather" in 模型输出` 判断,`json.loads()` 解析参数 | 框架自动识别 `tool_calls`、解析参数、执行对应函数 |
| ReAct 循环 | 自己写 `while` 循环判断要不要再转一轮 | `agent.invoke()` 内部封装了整个循环 |
| messages 维护 | 每轮结束手动 `messages.append(...)` | 框架内部自动管理消息历史 |

### 三、手写的价值体现在哪
(结论 + 今天的具体动作 + 日志证据)
- "我能一口咬定 [2][3] 的 content 是我的函数产生的"
- 因为这条链我亲手走过:Python 函数执行 → return 返回结果
  → 程序把结果写进 messages → 模型再读取继续判断
- 换来四样东西:理解 Agent 数据流 / 理解 tool calling 原理
  / 理解 messages 怎么拼接 / 知道 LLM 和 Python 谁负责什么
