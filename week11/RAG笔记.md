# 手写 RAG 笔记(第11周)

## 一、RAG 是什么
- **解决什么问题**:大模型两大短板——知识过时、不懂私有资料。
  RAG 只治"缺资料",治不了"缺智力"。
- **三步闭环**:检索 → 注入 → 生成。
  本质是提示工程:模型一个字节没改,改的只是喂进去的前文。
- **为什么不用微调**:微调=训练模型改参数,成本高、更新慢、不可溯源。
  想让模型"知道资料"选 RAG;想让它"学会风格腔调"才选微调。

## 二、五个环节 + 各自的坑
| 环节 | 在干嘛 | 我踩的坑 / 关键点 |
|------|--------|-------------------|
| 分块 | 把长文档切成有重叠的小段 | 封装成函数卡了一整天:450 不是常数,是 `chunk_size - overlap`。破法——从跑通的脚本里找写死的数字,问"调用者会想改吗" |
| 向量化 | 每块调 embedding API 转成数字存起来 | NumPy 数组不能直接存 json,存要 `.tolist()`、读回要 `np.array()` |
| 检索 | 问题转向量,和每块算余弦,取 Top-K | 猜字段名 `"vec"` 吃 KeyError——该先 `.keys()` 查。排序默认升序,搞反不报错、只是结果烂 |
| 注入 | 把 Top-K 原文拼进模板,和问题一起交给模型 | client 指向阿里云却填 DeepSeek 的模型名——平台和模型必须配对 |
| 生成 | 只依据资料作答,资料不足就说不知道 | 防幻觉那句是模板的灵魂。⚠️ temperature=0 同题两次答案仍有波动 |

## 三、核心公式(默写)
余弦相似度 = 数学:  cos(A, B) = A · B / (|A| × |B|)
            代码:  分子 = np.dot(a, b)
                  分母 = np.sqrt(np.sum(a**2)) * np.sqrt(np.sum(b**2))
                  防呆:分母为 0 → 返回 0

为什么它能衡量"相关":
embedding 模型承诺「意思相近 → 向量也相近」,余弦只是个量角器,
负责把这份相近度读出来。语义是 embedding 注入的,不是余弦算出来的。
→ 所以全程必须用同一个 embedding 模型(换模型=换担保人,旧向量作废)。
→ 所以检索不准,该查切块和排序,不是换公式。

## 四、我这周真正踩的坑

1. **参数名是格子,不是值。** 周二为此卡了一天;周六调用处又填了形参名
   而不是真数字——一天没治好的毛病,会换个地方再来找你。

2. **定义 ≠ 执行。** 函数名不加括号 = 念菜名不干活;main() 定义了从没被调用。

3. **变量不会自己飘过去。** index 在 main() 造好、search() 拿不到,
   得沿 main → ask → search 逐层传。不是程序找不到,是我没给它。

4. **复述五环节时漏了"注入"。** 单个问都答得出,串成链子走一遍就掉环——
   知识在脑子里是散的,不是一条链。

## 五、待优化(推到第14周)
- **块大小/重叠的调参**:靶心是"万能块"——一块塞了整章内容(市场规模/首钢/万得/蒋涛),
  跟任何问题算余弦都中等偏上,10 题里 8 题都捞到它,白占一个 Top-3 坑位。
  方向:切更小的块、按语义边界切而非按字数硬切。
- **检索准确率优化**:加重排序(rerank)、调 Top-K。
- **系统化评测**:本周的 10 题人工评测是基线,第 14 周拿它做前后对比。
