# 第16周 D6：A2A 概念笔记

> 一句话：**MCP 让 Agent 拿到工具，A2A 让 Agent 找到同行。** 对方的工具、记忆、内部步骤，你都看不到，也不需要看到。

```
A2A（Agent 和 Agent 之间，横着连）
你的客服 Agent  ───────────────────────►  快递公司的 Agent
     │           "帮我查这单到哪了"            │
    MCP                                       MCP
（竖着连，接自己的工具）              （竖着连，接它自己的工具）
     ▼                                         ▼
你的订单库、你的文件                   它的物流系统、它的数据库
```

---

## 1. A2A 解决什么问题？

**我的回答：** 解决不同公司、不同 Agent 之间的通信和协作。不用的话，每对接一个新公司、新 Agent 就要手写一套接口，成本极高。

**补充：**
- 5 个 Agent 两两单独约规矩，要约 **10 套**（6 个要 15 套，10 个要 45 套）；大家共用 A2A，只要 **1 套**
- 快递公司不会把数据库交给你做成 MCP 工具（里面有别家的单子和客户信息），所以只能请它的 Agent 帮忙查

## 2. 四个零件

**我的回答：** Agent Card（能力名片）→ Message（消息）→ Task（任务）→ Artifact（成品）。先看对方名片了解能力，接着发个消息提需求，对方建个任务去干活，最后交回成品给你。

| 零件 | 中文 | 网店里 |
|---|---|---|
| Agent Card | 能力名片 | 快递公司门口的服务说明：能办什么、在哪办、要什么 |
| Message | 消息 | 委托单上的一来一回沟通 |
| Task | 任务 | 一张有编号的委托单，有状态 |
| Artifact | 成品 | 办完交回的东西：物流截图、报价单 |

**补充：**
- 名片放在固定网址：`https://它的域名/.well-known/agent-card.json`（`.well-known` = 大家约定好的固定位置）
- A2A 走网络（HTTP），常用格式是 JSON-RPC（一封有固定格式的"请对方办事"的信）；MCP 在 D1 用的是 stdio，同一台电脑上直接拉起对方
- 对方回"单号不对，请再给一次"→ 任务状态是 **input-required**（停下来等你回话，没办完）；"办理中"是 working（对方在干活，你等着）
- 🔗 input-required 和第15周的 `interrupt` 是同一件事：一个从 Agent 内部看，一个从外面看
- 简单问题（"你们周末上班吗"）直接回一条 Message 就行，不用开 Task

## 3. MCP 和 A2A 各管哪一段？

**我的回答：** MCP 连接自家数据、工具；A2A 管 Agent 和 Agent 之间、和外部公司。例子：客服 Agent 用 MCP 查自家库存，用 A2A 向快递公司的 Agent 发消息查快递。

| | MCP | A2A |
|---|---|---|
| 连的是谁 | Agent ↔ 工具/数据 | Agent ↔ Agent |
| 对方是什么 | 看得见说明书的函数 | 看不见内部的同行 |
| 怎么知道对方能干什么 | 连上后 `list_tools` 问 | 去固定网址读名片 |
| 一次办事 | 调一次，马上回结果 | 开一张任务单，可能很久，中间能来回问 |

**补充：**
- 判断标准是"**对方是不是一个 Agent**"，不是"对方是不是自己人"：自家仓库 Agent 派活给自家财务 Agent，也是 A2A
- **站在谁的角度，答案不同：** 快递 Agent 查它自己的物流系统，站在它的角度是 MCP；站在你的客服 Agent 角度，那一步根本看不到，你只看到"发委托 → 收结果"这段 A2A

## 4. 为什么"分工不竞争"？

**我的回答：** 因为一个对工具，一个对同行，不冲突。一个 Agent 能同时用两个：先用 A2A 接外部单子，再用 MCP 调内部工具查资料，最后用 A2A 回复结果。

## 5. 我的 MCP 服务器要被别人委托，还缺什么？

**我的回答：** 缺一个具备思考能力的主 Agent。

**补充：** 我的 MCP 服务器只是一排工具（仓库），自己不会思考，所以首先缺"大脑"。另外还缺：
- **一张名片**（Agent Card），放在固定网址，让别人知道我能干什么
- **一个对外的 A2A 入口**：在网上开着（HTTP），能接委托、开任务单、交回成品

## 实操：给第15周旅行 Agent 写名片（`week16/agent-card.json`）

| 我的五栏 | 行号 | 字段名 |
|---|---|---|
| 名字 | 第2行 | `name` |
| 一句话说明 | 第3行 | `description` |
| 能办的业务 | 第18~26行 | `skills` |
| 要对方给什么 | 第22、24行 | `skills` 里的 `description` + `examples` |
| 会交回什么 | 第22行 | `skills` 里的 `description` |

- 名片初稿改过的地方：业务从三项（按天气/天数/预算）合并成一项（一项业务 = 别人能单独下一张委托单的事）；`budget` 是我算出来的，不是对方给的；天数不用交回；"审批结果"不是成品，而是办到一半要对方回答的事（input-required）
- **比喻对不上的地方：** 门口的服务说明会专门列"需要带什么"；A2A 名片里没有"要什么/交回什么"的专门字段，只能写成文字放在业务说明里，让对方的大模型自己读懂。`defaultInputModes` 只管格式（`text/plain`），不管内容
- JSON 里冒号左边是**字段名**（key），右边是**值**（value）。名片里有两个 `description`：第3行管整个 Agent，第22行管这一项业务

## 今天的教训：先查版本

- A2A 在 2026 年 3 月发布 v1.0（当前 v1.0.1）。v1.0 名片去掉了顶层的 `url`，改成 `supportedInterfaces`（每项写 url、protocolBinding、protocolVersion）；`capabilities` 里的 `stateTransitionHistory` 也去掉了；`skills` 里的 `tags` 是必填
- Claude Code 一开始列的是旧版字段，我和 Claude 也没核实就顺着说了，最后是读了官方原件 `a2a.proto` 才确认
- 🔗 和 D1 一样（mcp v1 的 `FastMCP` → v2 的 `MCPServer`）：**AI 记得的常是旧版本，能对上原件的以原件为准**
- 放行权限的判断：只读的也看来源（官方可以放，第三方选 1 或拦下）；选 2 之前看域名是一家独有还是大家共用（`raw.githubusercontent.com` 是共用的，只选 1）
