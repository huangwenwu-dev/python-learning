# 框架对比表

> 这张表是干什么的：别人问"做 Agent 用哪个框架"，翻开这张表就能答。
> 第17周 D6 整理，"谁在做、还更新吗"那一列查证日期：**2026-11-19**。

**用之前先核对：我装的是哪家哪版？手上的教程是哪年的？**

## 一、选框架速查表（七个框架）

| 框架 | 谁在做、还更新吗、最近大改 | 你主要写什么 | 最适合 | 什么时候别选 |
|---|---|---|---|---|
| LangGraph | LangChain 公司，还在更新；25年10月发 1.0 稳定版，之后小版本都向后兼容 | 画图：节点 + 边（条件边能分岔） | 每一步都要严格把控、带审批分岔的活（第15周旅行 Agent：路由函数定好批准走 book、拒绝走 replan） | 流程简单、急着出小样时（要亲手搭的零件太多） |
| CrewAI | crewAI 公司，更新很勤（我装的是 1.15.41） | 人设和工单 | 分工明确、有上下游依赖的流水线任务，上手快、出小样快（第17周作者+编辑：tasks 顺序让作者先写，context 让编辑拿初稿再改） | 每一步必须严格按规则走、不许出错时（D3：工单写了不许编造，作者还是编了"不缩水"） |
| AG2 | AG2 社区；老写法（`pip install autogen`）现在叫 AG2 Classic，只维护不更新；新版 AG2 v1.0（`pip install ag2`）改了写法 | 人设 + 开头 + 轮数 | 需要反复讨论的活（D5：编辑和作者来回改稿两轮） | 流程死板、要求确定性极高、不能有任何偏差的活；或要省钱省时间时（来回聊得越多越贵越慢） |
| OpenAI Agents SDK | OpenAI，还在更新，26年4月15日大改过 | 没用过 | 着急出小样、单个 Agent 调工具的活 | 主力模型不是 OpenAI 家的时候（能接别家，但不是给别家优化的） |
| Claude Agent SDK | Anthropic，更新很勤；25年9月由 Claude Code SDK 改名而来 | 没用过 | 复杂编程任务、需要人中途确认 | 主力模型不是 Claude 的时候（比如用 DeepSeek）；简单固定流水线也犯不上 |
| Pydantic AI | Pydantic 团队，更新很勤，26年6月23日大改（发布 v2） | 没用过 | 带校验的结构化输出（D3：终稿和修改清单混在一起交，数出 421 字；分栏交就不会混） | 多个 Agent 按复杂先后顺序交接的活（推测） |
| Microsoft Agent Framework | 微软，还在更新，26年4月3日发布 1.0 正式版 | 没用过 | 企业级、需要长期稳定运行的生产项目 | 快速做个小样，或个人小项目时（零件多、配置多，杀鸡用牛刀） |

**通用规矩：** 已经定了用哪家模型，就优先看那家自己出的 SDK；主力模型不是它家的，它家 SDK 就别选。

**先看手里有什么：** 选框架前先看自己手里已经有什么，现成能跑的往往最快。

## 二、三个用过的框架怎么运转（第17周 D5 整理）

| | LangGraph（第15周） | CrewAI 顺序模式（第17周） | AG2（D5 读的） |
|---|---|---|---|
| 你主要写什么 | 图：节点和边 | 人设 + 工单 | 人设 + 开个头（谁找谁、第一句、几轮） |
| 谁决定下一步 | 路由函数（代码写死） | tasks 列表顺序 | 两人固定轮流；说什么由模型定，轮数到了就停 |
| 像网店里的什么 | 带分岔的审批流程 | 流水线 / 交接单 | 拉个工作群开会 |
| 结果好不好预测 | 最好预测：每条路都写死了 | 较好预测：顺序固定，每站内容由模型写 | 最难预测：每句接上一句，容易越聊越偏 |
| 适合干什么 | 步骤清楚、要严格把关的事 | 分工明确、一站接一站的活 | 需要反复讨论、互相挑毛病的活 |

注：D5 读的 AG2 代码（`ConversableAgent`、`initiate_chat`）是 AG2 Classic 的老写法。
